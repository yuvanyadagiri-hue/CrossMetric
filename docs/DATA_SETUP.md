# Data setup

Everything CrossMetric shows is rebuilt from public sources by the pipeline. Raw downloads (`data/raw/`) and intermediate tables (`data/interim/`) are git-ignored; the published analysis (`data/published/`, ~175 MB) is regenerated by `python -m pipeline.run`.

## 1. Python environment

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[db,dev]"      # macOS/Linux: .venv/bin/python
```

Exact versions used for the competition build are pinned in `requirements.lock.txt`.

## 2. Fetch sources

| Step | Command | Source | Time |
|---|---|---|---|
| Schools | `python -m pipeline.ingestion.schools` | NCES EDGE geocodes + CCD admin data (ArcGIS REST) | < 1 min |
| Crashes | `python -m pipeline.ingestion.crashes` | GDOT GeoPI Crashes, ~1.25 M records, 251 pages, resumable cache | ~30 min |
| Signals, AADT, stations, HIN | `python -m pipeline.ingestion.reference_layers` | GDOT, ARC (ArcGIS REST) | ~2 min |
| Road inventory | download + unzip (below), then `python -m pipeline.ingestion.roads` | GDOT Office of Transportation Data | ~5 min |
| Street names | `python -m pipeline.ingestion.tiger_names` | Census TIGERweb, ~4,800 tile requests near schools | ~10 min |

GDOT Road Inventory (one-time, 766 MB):

1. Download `Road_Inventory_Geodatabase.zip` from <https://www.dot.ga.gov/GDOT/Pages/RoadTrafficData.aspx> (direct link: `https://myfiles.dot.ga.gov/OTD/RoadAndTrafficData/Road_Inventory_Geodatabase.zip`).
2. Unzip into `data/raw/road_inventory/` so that `data/raw/road_inventory/Road_Inventory_2025_Geodatabase.gdb` exists.

Every ArcGIS source is schema-checked before use. If a publisher renames a field or changes a type, the step stops with a message such as `[gdot_crashes] schema INVALID; missing fields: INJURIES`.

## 3. Build and validate

```bash
python -m pipeline.run                    # build (~10 min) + publish (~1 min)
python -m pipeline.run --publish-only     # re-publish from data/interim without rebuilding
python -m pipeline.validation.run         # validation experiments -> data/published/validation.json
python -m pipeline.scoring.parity         # refresh the Python/TypeScript parity fixture
python -m pytest                          # includes the data-contract test on the output
```

Development shortcut: `python -m pipeline.run --limit 25` processes only the first 25 schools.

### CrossMetric 2.0 additions (run after `pipeline.run`)

```bash
python -m pipeline.ingestion.colleges          # IPEDS HD 2024-25 (downloads ~1 MB): 110 Georgia degree-granting colleges
python -m pipeline.institutions                # college candidates + packages -> data/published/colleges/ (~2 min)
python -m pipeline.publish.statewide           # route-scoring indexes + map layers -> data/published/statewide/ (~6 min)
python -m pipeline.publish.statewide --references-only   # recompute only the CrossScore reference distributions
```

`pipeline.publish.statewide` also downloads MARTA's public GTFS feed (~19 MB) on first run. Colleges are built in their own pass, so they never change a K-12 school's candidates or rankings.

### Commuter app data (Georgia Tech and UGA)

The commuter app needs only these two steps; it does not depend on the crash pipeline.

```bash
python -m pipeline.commute.campus      # buildings, entrances, parking shapes from OpenStreetMap (cached in data/raw/osm/)
python -m pipeline.commute.transit     # timetables: MARTA, UGA Campus Transit, Athens-Clarke County Transit GTFS
```

Outputs go to `data/published/commute/`. Hand-verified rule records (parking rules and rates, night services, service-calendar exceptions, game days, help numbers) live in `data/commute/gt.json` and `data/commute/uga.json`, each fact with a source URL, the date it was checked and a re-check date. **Re-verify these against the official pages before each release**: a record past its re-check date makes every affected parking place show "Rules unknown" instead of guessing. Delete `data/raw/*_gtfs/` to fetch fresh GTFS feeds (the UGA Passio feed is regenerated daily).

### Live services used by the web app (no keys needed)

| Variable | Default | Used for |
|---|---|---|
| `VALHALLA_URL` | `https://valhalla1.openstreetmap.de` (FOSSGIS, fair use) | Routing and OpenStreetMap street attributes |
| `GEOCODER_URL` | `https://photon.komoot.io` (fair use) | Address and place search, limited to Georgia |
| `COMMUNITY_DATA_DIR` | `data/community` | Community reports, parking reports and research feedback when `DATABASE_URL` is not set |
| `NWS_USER_AGENT` | `Crossmetric/3.0 (student commuter app)` | National Weather Service asks for an identifying User-Agent; add a contact URL or email for production |
| `CROSSMETRIC_COMMUTER_HOME` | on | `0` shows the previous dashboard at `/` (read per request; no rebuild needed) |
| `OBSERVATION_SALT` | random per process | Salt for hashing anonymous device keys of parking reports; set it so rate limits and undo survive restarts |
| `CROSSMETRIC_INTERNAL_TOKEN` | unset (disabled) | 16+ characters enables the internal research workspace at `/internal/research` |
| `RESEARCH_PIPELINE_ENABLED` | on | `0` is the research pipeline's kill switch |

For heavier use, run your own Valhalla and Photon and point these variables at them. Requests are made by the CrossMetric server (a visitor's IP is never forwarded) and cached.

### Uber handoff (one public ID)

"Continue in Uber" hands a reviewed rideshare trip to Uber's documented [ride-request universal link](https://developer.uber.com/docs/riders/ride-requests/tutorials/deep-links/introduction) (`https://m.uber.com/looking?client_id=…&pickup=…&drop[0]=…`). Uber shows prices, checks availability and the rider's account, and the rider requests the ride there. It needs only:

| Variable | Default | Used for |
|---|---|---|
| `NEXT_PUBLIC_UBER_CLIENT_ID` | none — the button stays disabled and says why | The **Client ID** of your app in the [Uber developer dashboard](https://developer.uber.com/dashboard). Public by design (it is in every link). |

Put it in `apps/web/.env.local` and restart or rebuild (Next.js inlines `NEXT_PUBLIC_` values at build time). Never add a client secret or server token: the handoff uses no Uber OAuth and no Riders API access, which Uber restricts to approved partners. Link construction lives in `apps/web/src/lib/uber.ts`.

## 4. Supabase PostgreSQL + PostGIS (optional for local use, recommended for deployment)

1. Create a Supabase project. In **Database → Extensions**, PostGIS is enabled by the migration itself (`create extension if not exists postgis`).
2. Apply the migrations in order, either in the Supabase SQL editor or with `supabase db push`:
   - `supabase/migrations/20261003000001_crossmetric_schema.sql`
   - `supabase/migrations/20261003000002_crossmetric_functions.sql`
   - `supabase/migrations/20261005000001_community_reports.sql` (community reports; used automatically when `DATABASE_URL` is set)
3. Load the data. Copy the **connection string** from Project Settings → Database into an environment variable yourself (never commit it):

   ```bash
   set DATABASE_URL=postgresql://postgres:...@...supabase.co:5432/postgres
   python -m pipeline.publish.postgis              # schools, candidates, crashes near schools, AADT, analyses, validation
   python -m pipeline.publish.postgis --with-roads --with-quarantine   # optional extra tables
   ```

4. Point the web app at it: create `apps/web/.env.local` containing `DATABASE_URL=...`. The app switches from files to PostGIS automatically; the Methodology page's *Version* section shows which storage is active.

Approximate size with the default load: ~520k crash rows, 236k candidate locations, 2,336 schools and reference analyses. Supabase's free tier (500 MB) is tight; the `--with-roads` and `--with-quarantine` options add roughly 100–150 MB.

Verification status: both migration files parse with PostgreSQL's own parser (`pglast`), and the data-contract test checks the published data against every table constraint. The loader has not yet been run against a live Supabase instance from this repository.

## 5. Web app

```bash
npm install
npm run dev            # copies the MapLibre worker into public/, then starts Next.js
npm run build && npm start
```

`CROSSMETRIC_DATA_DIR` overrides where the file repository reads published data (default `../../data/published` relative to `apps/web`).
